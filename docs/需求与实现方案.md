## 二、新增的技术事实（本次探测，可复现）

| 探测 | 结果 | 结论 |
|---|---|---|
| `GET chat.deepseek.com/api/v0/chat_session/fetch_page`（无鉴权） | `200` + `{"code":40003,"msg":"INVALID_TOKEN"}` | 会话列表接口存在，鉴权走 token |
| `POST …/users/login`（裸 curl） | `429`，WAF 页 "Rate Limit Reached" | 裸请求会被风控挡；**必须带浏览器请求头**（UA / Origin / Referer / `x-client-*`） |
| `POST …/users/login`（带浏览器头） | `422`，`detail` 列出 `body.password`、`body.device_id`、`body.os` | 登录体至少需要这三项 |
| `POST …/users/login`（带 email+password+device_id+os） | `422`，`detail: [{loc:"body.1"}]` | FastAPI 联合体校验：邮箱与手机号是**两个候选分支**，真实字段组合要用真账号在 P0 定稿 |

> 说明：这三次探测都**没有**携带任何凭据，只用于确认接口形状。真实登录验证放在 P0，用你填进 JSON 的账号，脚本只打印脱敏后的状态码与错误码，绝不打印密码或 token。

## 三、实现方案（A2 全链路）

### 3.1 架构

```
┌──────────────── 浏览器（DSH Web） ────────────────┐
│ client.js                                         │
│  ├─ 侧栏注入：工作区区头 / 对话区（含折叠）        │
│  ├─ 新会话页：Work–Chat 分段开关                   │
│  ├─ 设置页：DeepSeek 账号表单（邮箱/手机号+密码）  │
│  └─ 主面板：对话视图（消息流 + 输入框）            │
└───────────────┬───────────────────────────────────┘
                │ 同源 HTTP（仅回环，Origin 校验）
┌───────────────▼──────────── Host 插件 ────────────┐
│ index.js → routes.js                              │
│  ├─ auth.js   ：login / token 缓存 / 401 重登      │
│  ├─ sync.js   ：会话列表、历史消息、流式补全       │
│  ├─ store.js  ：$DSH_HOME/workchat/*.json 持久化   │
│  └─ redact.js ：日志与错误信息脱敏                 │
└───────────────┬───────────────────────────────────┘
                │ https（浏览器头 + Bearer token）
        chat.deepseek.com 网页端接口
```

### 3.2 账号与登录（A2 核心）

**配置入口**：设置页新增「DeepSeek 网页账号」分区 → 邮箱（或手机号+区号）、密码 → 保存 / 测试连接。

**登录流程**：

0. **优先 userToken**（P0 实测结论：密码登录被 AWS WAF 拦截）。用户从网页版 F12 → Local Storage 复制 `userToken`，或从任意请求头取 `Bearer` 值；插件拿到后只做一次最小列表请求验证。
1. 无 userToken 时才回退账号密码：读取凭据（设置页 `$DSH_HOME/workchat/credentials.json` 优先，插件目录 `secrets/deepseek-credentials.json` 兜底）。
2. `POST https://chat.deepseek.com/api/v0/users/login`
   - Header：`Content-Type`、`Accept`、`Origin`、`Referer`、浏览器 UA、`x-client-platform: web`、`x-client-version`、`x-app-version`
   - Body：`{ email | (mobile + area_code), password, device_id, os: "web" }`
   - `device_id` 首次生成 UUID 后固定复用（换设备 ID 可能触发风控）
3. 解析 `data.biz_data.user.token`（具体路径 P0 用真账号定稿），得到 `userToken`。
4. `userToken` 只存内存 + `$DSH_HOME/workchat/auth.json`（0600）；**不存明文密码到 token 文件**。
5. 任何接口返回 `40003` / HTTP 401 → 自动用保存的账号密码重登一次，仍失败则标记「需要重新登录」并在设置页提示。

**风控与失败处理**：
- 收到 429 → 指数退避（10s / 30s / 60s），并提示"触发网页端风控，稍后再试"。
- 若接口要求 PoW 挑战（`x-ds-pow-response`），P0 会暴露出来；届时在 Host 侧实现 SHA3-256 求解，属于可控工作量，但会延长 P0。
- 所有请求串行化（单飞），避免并发触发风控。

### 3.3 同步服务

| 能力 | 接口（待 P0 定稿参数） | 说明 |
|---|---|---|
| 会话列表 | `GET /api/v0/chat_session/fetch_page` | 拉取最近 N 条，落缓存 `conversations.json` |
| 历史消息 | `GET /api/v0/chat/history_messages?chat_session_id=…` | 点开对话时按需拉取并缓存 |
| 发送消息 | `POST /api/v0/chat/completion`（SSE 流） | Chat 模式发送即走这里，服务端自动建会话 |
| 鉴权 | `Authorization: Bearer <userToken>` | 401/40003 触发重登 |

### 3.4 需求 1：工作区整体折叠

- `sidebar.workspaces` 是 single 槽，被工作区浏览器独占 → 无法在槽内加区头。
- **做法**：在 `regionArea` 内、`[data-slot="sidebar.workspaces"]` 之前注入区头节点，`MutationObserver` 维持；点击给容器打 `data-workchat-workspaces="collapsed"`，CSS 隐藏槽位。
- 交互：悬停底色加深（复用 `--dsh-sidebar-*` 与主题色，左右内缩 3px）、箭头旋转、`aria-expanded`、键盘 Enter/Space、`prefers-reduced-motion` 降级、状态存 `localStorage`。
- 56px 轨道态与移动端抽屉不显示区头（外壳本身不渲染该区域）。

### 3.5 需求 2：对话区（网页端同步）

- 与工作区同一个 `regionArea`，顺序：工作区 → 对话区 → 设置。
- 区头组件与需求 1 **共用**（悬停/折叠/记忆），各自独立的状态键。
- 列表行：标题、相对时间、来源徽标（`网页`）、未读点；排序按 `updated_at` 倒序。
- 数据：Host 每 60s 拉一次列表（可关），点击区头手动刷新；浏览器只读 Host 缓存。
- 点击 → 主面板打开对话视图（决策 C）：先渲染缓存消息，同时拉最新历史；输入框可继续发消息。
- 空态 / 未登录 / 同步失败：三种占位文案，失败时给"重试"与"去设置"两个入口。

### 3.6 需求 3：Work / Chat 开关

**落点**：`conversation.header` 槽，水平居中，仅 `[data-phase="hero"]`（空白新会话）显示。

| 位置 | Work | Chat |
|---|---|---|
| 开关 | 左段高亮 | 右段高亮 |
| 工作区 chip + 预设行 | 原样 | 整行隐藏 |
| Agent 预设（开发模式） | 原样 | 隐藏 |
| 权限预设（审核模式） | 原样 | 隐藏 |
| 计划模式等其余按钮 | 原样 | 隐藏 |
| 模型选择 | 原样 | 保留 |
| 发送 | 现有流程 | 走 `/api/v0/chat/completion`，新建网页端会话 |

**实现**：`<html data-workchat-mode="chat">` + 一条作用域 CSS，命中官方锚点：

```css
html[data-workchat-mode="chat"] [class*="heroWorkspaceRow"],
html[data-workchat-mode="chat"] [data-slot="conversation.input.permission"],
html[data-workchat-mode="chat"] [data-slot="conversation.input.plan"] { display: none; }
```

**Chat 发送时序**：回车 → 建本地记录并立刻进「对话区」→ 主面板打开 → SSE 流式回复 → 回写标题/摘要 → 同步列表。

## 四、账号密码文件与安全边界

已创建：`dsh-work-chat/secrets/deepseek-credentials.json`（字段为空，等你填）

```json
{
  "email": "",
  "mobile": "",
  "areaCode": "+86",
  "password": "",
  "deviceId": "",
  "os": "web"
}
```

**边界（按你的要求）**：

1. **模型不读这个文件**：我不会 `read` / `cat` / 打开它；只有 `tools/probe-login.mjs` 这类**程序**在开发验证时读取。
2. 我已加 `.gitignore`（`secrets/*.json`），不会随插件包或仓库外泄。
3. 测试脚本只输出：HTTP 状态、业务 code、token 是否存在（`present: true/false`），**永不打印**密码、token 或凭据片段。
4. 设置页写入的运行期凭据放在 `$DSH_HOME/workchat/credentials.json`，插件目录那份仅作开发测试夹具。**注意**：Windows 上 Node 的 `0600` 只影响只读位，不构成权限隔离；需要更强隔离时用 `icacls` 收紧目录（插件不自动执行系统命令）。
5. **路由鉴权边界**：`/workchat/*` 走回环 + 同源校验（防浏览器 CSRF），但**不**接入 DSH 页面自身的 401 登录态——本机其它进程仍可调用。可接受的理由是：本机进程本来就能读取同一份凭据文件；若要更严，后续可加一次性配对令牌。
5. **风险提示（需要你知情）**：密码会以明文落盘。建议验证通过后二选一：① 保留但确保该目录不备份到云盘/不同步；② 改用"粘贴 userToken"模式（不存密码，token 过期再换）。这条列在 §八 的待确认里。

## 八、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 网页端接口非公开，可能改版 | 同步失效 | 接口层集中在一个文件；失败降级为只读缓存 + 明确提示 |
| 风控（429 / 设备指纹 / PoW） | 登录或发送被拒 | 浏览器头、单飞、退避、固定 device_id；必要时实现 PoW |
| 明文密码落盘 | 凭据泄露面 | gitignore、只本机、不进日志；Windows 权限需 `icacls` 额外收紧；可改为 token 模式（§四 第 5 条） |
| 侧栏 DOM 注入 | DSH 升级后失效 | 只依赖 `data-slot` 官方锚点，失效可降级为替换侧栏外壳 |
| 账号被封禁风险 | 影响你正常使用 | 请求频率贴近正常用户（列表 60s 一次），不做批量抓取 |
