## 二、一条命令验证（不需要页面）

```powershell
$node = '%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$root = '<插件目录>'
foreach ($t in 'smoke-client','smoke-sidebar','smoke-host','smoke-vendor') { & $node "$root\tools\$t.mjs" }
```

全部返回 `"ok": true` 即为通过。

## 三、已知问题与取舍

1. **列表上限 100 条**：网页端 `fetch_page` 无可用游标，超过 100 条拿不到更早的。
2. **原生导入默认关闭**：`POST /workchat/import` 可用，但会让会话额外出现在工作区，按你的要求点击对话不再自动导入。
3. **composer 接管在空白页无效**：宿主传 `fallbackOnly: sessionId === undefined`，所以 Chat 模式的输入框由「对话区面板」承载。
4. **vendor 体积**：marked + KaTeX + 字体约 0.55MB，启动时自检会加载一次（本机读取，很快）；若想去掉，删掉 `apply` 里的 `selfTestRenderer` 调用即可。
5. **测试会话**：验证时导入的两个会话（标题「DeepSeek 网页对话」）仍在工作区，宿主持久化没有 delete 接口，需要手动删。
6. **折叠实现方式**：靠 DOM 注入 + `data-slot` 锚点，DSH 大版本升级后需回归检查（锚点消失会降级为“仅对话区”）。

## 四、回滚

```
plugin_manager remove_bundle target = dsh-work-chat
```

卸载后注入的区头/样式/心跳都会随 `ctx.effect` 清理；数据仍在 `$DSH_HOME/workchat/`，不需要时整体删除即可。
