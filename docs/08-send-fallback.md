# M8 · 发送闭环与回退

## 目标

Chat 模式下发送一条消息，端到端完成：**建会话 → 流式回复 → 进对话区 → 可继续**；网页端不可用时按你的确认 2 **回退**到 DSH 本地模型。

## 触发点

1. 新建 Chat 页（hero）的 `ChatComposer` 回车 / 点发送。
2. 对话页 composer 的发送。

两者共用 `sendMessage()`。

## 主流程（网页端）

```
输入 → 校验非空 → 乐观插入用户气泡 → 锁 UI（data-workchat-busy）
     → POST /workchat/chat (SSE)
        ├─ meta  → 拿到 sessionId：新建时立刻写入对话区并选中、切到主面板
        ├─ delta → 追加到助手气泡（节流 60ms 渲染）
        ├─ error→ 进入回退判断
        └─ done → 落盘、刷新侧栏时间、解锁
```

- **新建页发送后**：自动 `selectPanel('workchat')` 打开对话页，输入框内容清空，思考/搜索偏好写入新会话。
- **对话页发送**：只更新当前会话，不切面板。
- **停止**：发送中发送按钮变「停止」，点击 abort fetch，已收内容保留并落盘。

## 回退策略（你的确认 2）

| 情况 | 处理 |
|---|---|
| 网络不可达 / 5xx / 429 连续失败 | 回退 |
| `40003` 且重登失败 | 回退 |
| 用户未配置账号 / 未登录 | 直接回退（不弹错） |
| 内容被风控拒绝（业务码语义明确） | **不回退**，提示原因，避免掩盖真实问题 |

回退动作：

1. 调用 `ctx.uiWorkspace.startSession(undefined, { prompt })` 建立本地会话（等价 Work 流程）。
2. 顶栏 toast：「网页端不可用，已切换为本地会话」。
3. 模式切回 `work`，本地面板关闭，选中新会话。
4. 本次对话不写入网页端；侧栏对话区不新增条目。

> 说明：回退的是**发起方式**，不是把同一条消息同时发两处——避免重复计费与重复记录。

## 失败文案

| stage | 文案 |
|---|---|
| `input` | 请先填写账号密码（附"去设置"） |
| `auth` / `unauthorized` | 登录已失效，已尝试重新登录 |
| `rate-limited` | 网页端限流，请稍后再试 |
| `network` | 网络不可达 |
| `http` | 网页端返回异常（HTTP xxx） |
| `fallback` | 已回退为本地会话 |

文案里不出现 token、密码、响应体。

## 幂等与重复

- 同一会话内禁止并发发送；`data-workchat-busy` 未清除前忽略再次回车。
- 乐观消息带临时 id，`done` 后用服务端返回的 id 替换；失败回退时移除乐观气泡。

## 验收

- [ ] 新建 Chat 发送 → 侧栏对话区出现新条目 → 主面板显示流式回复。
- [ ] 对话页继续发送 → 追加到同一会话，网页端能看到。
- [ ] 断网/错密码 → 自动回退为本地会话，toast 正确，无重复消息。
- [ ] 点停止 → 流中断，已收内容保留。
- [ ] 连点发送不会产生两条。

## 风险

- 回退依赖 `ctx.uiWorkspace.startSession` 的可用性；该服务缺失时降级为 toast 提示"请手动切到 Work"。
- 流式渲染节流不当会掉帧：统一 60ms 批处理。
